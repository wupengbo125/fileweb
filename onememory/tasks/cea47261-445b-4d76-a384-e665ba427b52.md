# 2026-09-28 fileweb 新建目录/文件 + 重命名

## 诉求
手机上能建文件夹、建文件（建完直接进编辑页）、给已有条目改名。重名一律报错，不自动改名、不覆盖。

## 决策
- 入口放右下角「+」菜单，加「新建文件夹」「新建文件」两项，不碰原有上传/同步
- 重名报错 vs 自动改名（上传走 unique_path 自动改名）：用户拍板报错，跟上传策略故意不一致
- 不拦点开头名字（.gitignore 要建得出来），只拦 .git 这一个名字
- 重命名触发方式：长按 0.6s，不动现有左滑删除手势；用户未反对

## 代码结论
- `check_name()`：新建/重命名共用取名规则（空、斜杠、控制字符、>255 字节、.git）
- 写目标一律先查 `is_symlink()`：断链软链 `exists()` 为假，不拦会顺链写到 ROOT 外
- 保存 `/api/file` 本来就安全：`safe_path` 的 `resolve()` 跟软链，指向 ROOT 外直接 403，无需改
- 检查与创建/改名放进同一个 `_LOCK`，防并发 TOCTOU 覆盖同名
- 上传是唯一另需补预检的写路径（`dest = p / name` 没过 safe_path）

## 三轮评审
1. 阻塞：建文件后没 `render(cur)`，关编辑页列表是旧的 → 补 await render
2. 通过：断链软链漏洞、.git 误建、`render` 未 await
3. 用户拍板：既有软链风险一并修，并补重命名

## 验证
重启常驻进程后 curl 逐条过：建目录、建空文件、重名、非法名、超长名、断链软链（上传/新建均拒，/tmp 外无文件）、越界保存 403、重命名文件/文件夹/撞同名/改根目录、清理删除。无残留。
